# 06 · M5 收尾：调参、多样性、贪心融合

## 超参数搜索（Optuna）

### 第一版搜索失败了，原因值得记

我把搜索空间设成 `learning_rate ∈ [0.01, 0.08]`、`num_leaves ∈ [16, 256]`、
`max_depth ∈ [3, 14]`，结果单组参数要跑 5-10 分钟：
低学习率意味着要上千轮才收敛，256 个叶子又让每轮变慢。
按这个速度 40 组要跑一个多小时。

**修法不是加机器，而是砍掉不必要的区域。** M3 已经证明"更大容量没有帮助"，
所以把 `num_leaves` 上限收到 128、`learning_rate` 下限抬到 0.02、
迭代上限压到 2500，单组降到 100-150 秒。最终 40 分钟跑了 17 组。

> 教训：**调参前先想清楚"哪个区域已经被证伪"**，
> 把这部分从搜索空间里去掉，比去优化搜索算法本身更省时间。

### 结果

3 折搜索最优 AUC = 0.960229，最优参数：

```json
{
  "smooth": 13.59, "learning_rate": 0.0330, "num_leaves": 47,
  "min_child_samples": 87, "feature_fraction": 0.592,
  "bagging_fraction": 0.988, "lambda_l1": 0.737, "lambda_l2": 2.987,
  "max_depth": 10
}
```

有意思的是它收敛到**比手工基线更小、正则更强**的区域
（叶子数从 64 降到 47，L2 从 0.1 提到 3.0），
和 M3 的结论（大容量无益）完全一致。这不是巧合——
合成数据信噪比高，模型早就够用了，多出来的容量只会去拟合噪声。

### 然后用 5 折重新验证

| 配置 | OOF AUC |
|---|---|
| 手工基线（leaves=64, lr=0.03, m=2） | 0.960325 |
| Optuna 最优参数（m=5） | **0.960343** |

**只涨了 0.00002。**

这是个诚实但不好看的结果：花 40 分钟调参，收益是噪声量级。
它同时也是一份有价值的证据：**这个数据上，超参数不是杠杆。**
如果一开始就做调参而不做表示（目标编码），我们会一无所获。

## 用多样性换融合增益

### 上一轮融合给了一个明确信号

3 模型融合时，贪心选择把**最大的权重**给了相关性最低（0.97）的
`te_fine`，而不是最强的 `lgb_tuned`，也不是单独分数第二的 `xgb`。

这符合融合的原理：**增益来自误差的互补，不来自成员的平均实力。**
于是这一轮我不再追求"更强的模型"，而是刻意制造"结构不同的模型"：

| 模型 | 差异来源 | OOF AUC |
|---|---|---|
| `lgb_et` | `extra_trees=True`，分裂阈值随机化 | 0.955233 |
| `lgb_goss` | GOSS 单边梯度采样 | 0.960260 |
| `xgb_deep` | `grow_policy=lossguide`，深树 | 0.960334 |

`lgb_et` 单独分数掉了 0.005（随机分裂确实伤性能），
但它和所有人的相关性只有 0.94-0.95，是所有成员里最低的。

## 换掉权重搜索方法：Caruana 贪心集成选择

原来用 Nelder-Mead 单纯形法直接优化权重。成员增加到十几个后，
单纯形法在 14 维以上开始退化，而且每评估一次 AUC 是 O(n log n)，
单次搜索要十几分钟。嵌套交叉验证要做 5 次，完全不可接受。

改用 **Caruana 贪心集成选择**（*Ensemble Selection from Libraries of Models*, 2004）：

1. 起点选单模型里最好的那个；
2. 每一步，从所有模型里挑一个"加入后整体 AUC 提升最多"的；
3. 有放回地重复 30 步，最终的权重 = 被选中次数 / 总步数。

它天然满足非负、归一化，天然在整数格点上搜索，
在十几维这个规模上比单纯形法稳得多，而且**可以解释**——
每一步都是一次"当前组合最缺什么"的显式决策。

## 最终结果

| 融合成员数 | 等权排名平均 | 贪心权重（嵌套 CV） |
|---|---|---|
| 3 | 0.960462 | 0.960466 |
| 14 | 0.960620 | 0.960713 |
| **17** | 0.960619 | **0.960738** |

最终权重分布（很能说明问题）：

```
te_fine              0.290   <- 单模型 AUC 只有 0.96016，但相关性最低
xgb_deep             0.226
te_dist_ob_cls_cat   0.194
cat                  0.129
te_all_nofd          0.097
lgb_tuned            0.032
te_all               0.032
lgb_et               0.000   <- 太弱，被淘汰
其余 9 个             0.000   <- 与已选成员高度冗余
```

**14 个模型拿到 0 权重**。这不是算法没找到它们，而是它们提供的信息
已经被权重非零的那 7 个覆盖了。成员多不代表融合好，
**只有"提供新信息"的成员才算数。**

## 全程线上验证

| 阶段 | 本地 OOF | 线上公开榜 |
|---|---|---|
| M2 基线（纯 LightGBM，原始特征） | 0.958910 | 0.95843 |
| M4 三模型融合（+ 航线目标编码） | 0.960505 | 0.96021 |
| M5 十四模型贪心融合 | 0.960713 | 0.96028 |
| **M5b 十七模型贪心融合（最佳）** | **0.960738** | **0.96029** |

本地提升 0.00183，线上提升 0.00186。**方向完全一致**，
这也再次确认了从 M2 开始建立的那条原则是对的：
只要 CV 可信，就可以放心地只在本地优化。

### 一个需要诚实的观察

从 M5 到 M5b，本地 OOF 涨了 0.000025，线上只涨了 0.00001。
而 M4 到 M5 本地涨 0.00021，线上只涨 0.00007。

也就是说**最近这两步的改进幅度已经小于公开榜自身的噪声**（约 ±0.0005）。
这不是模型没变好，而是公开榜只用了 6 万行测试样本，
分辨不出 0.0002 这个量级的差异。

### 名次

| 阶段 | 公开榜名次 |
|---|---|
| M2 基线 | 346 / 595 |
| M5b 最终 | **248 / 612** |

榜单分位（612 条成绩）：中位数 0.95898，75% 分位 0.96109，
第 100 名 0.96130，第 1 名 0.96167。
我们从"略低于中位数"走到"中位数与 75% 分位之间"。

## 回头看不成立的尝试（按"花的力气"排序）

| 尝试 | 结论 |
|---|---|
| 加入外部原始数据集（4 种权重） | 无增益，等权时有害 |
| 手工特征工程（15 个统计/交互特征） | 有害，特征越多越差 |
| 提高模型容量（3 倍叶子数） | 无增益 |
| `id` 泄漏 | 不存在 |
| 折内再折编码 | 无增益（自泄漏量级太小） |
| 追加 3 个高基数编码键 | 无增益 |
| 平滑强度扫描 | 极平坦，几乎不影响 |
| **超参数搜索（40 分钟）** | **+0.00002** |
| **航线距离目标编码** | **+0.0014 ← 唯一的大杠杆** |
| **多模型贪心融合** | **+0.0004** |

十个方向里只有两个有效，而最大的那个（目标编码）来自
"发现信号藏在高基数结构里"这一个判断。

## 关于最终提交

`numScoredSubmissions = 2`：比赛要求在"我的提交"页面勾选 **2 份**
最终提交用于评分。如果不选，Kaggle 会按规则自动选。
这一步是网页上的操作，API 不提供。

## 下一步可以做什么

1. **10 折代替 5 折**：每个模型多用 10% 的训练数据，航线编码也更稳。
2. **多随机种子平均**：把方差再压一点。
3. **伪标签**：用置信度高的测试集预测扩充训练集。
4. **神经网络**：真正不同族的模型，可能带来比 GBDT 变体更大的互补性。
