# 00 · 总体思路

## 先想清楚：这个任务是"什么形状"的问题

在写任何代码之前，先明确约束条件——这决定了后面所有取舍。

1. **指标是 ROC AUC。** 这意味着：
   - 我们只需要输出**概率/分数**，不需要自己定阈值；
   - 只要能把正样本排得比负样本更靠前，分数就高；
   - 因此**排序能力**比"分类准确率"重要，AUC 对类别不平衡不敏感。
2. **这是合成数据（Playground 系列）。** 这类数据通常：
   - 噪声比原始数据小、可学习性强；
   - 上限高、分数密集（头部几百个队可能只差 0.0005）；
   - 因此**最后拼的是细节**：特征处理、融合、交叉验证稳定性，而不是"用哪个神奇模型"。
3. **每天只能提交 10 次。** 意味着不能靠"狂交"来调参，必须靠
   **本地交叉验证 (CV) 分数**来做决策，把线上提交当作最终验证而非探索工具。

## 决策原则

- **一切用 CV 说话**：任何特征、模型、参数的改动，只有 CV 变好才保留。
- **先建立可信的验证框架**：折数固定、随机种子记录、CV 与线上分数要能对上，
  否则后面所有实验都是在噪音里找信号。
- **复杂度最后加**：先要一个能跑通并且提交成功的基线，再逐步加深。

## 里程碑

| 里程碑 | 目标 | 完成标准 |
|---|---|---|
| M1 | 打通链路 | 本地能跑通、Kaggle 上有一个非报错的提交 |
| M2 | 强基线 | 单模型 CV AUC 达到有竞争力的水平 |
| M3 | 特征工程 | 通过 CV 验证的特征改进 |
| M4 | 融合 | 融合模型 CV 明显优于单模型 |
| M5 | 收尾 | 选定最终提交，文档与代码可复现 |

## 风险与未知

- 数据列结构、缺失值分布尚未确认 → M1 用 EDA 先看清楚。
- 交叉验证分数与线上分数可能不一致 → M1 提交后立刻核对偏差。
